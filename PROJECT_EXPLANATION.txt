================================================================================
1. АРХИТЕКТУРА ПРОЕКТА
================================================================================

Проект построен по принципу Clean Architecture с разделением backend и frontend:

  O_Shop/
  ├── .gitignore              — файлы, которые НЕ попадут на GitHub
  ├── PROJECT_EXPLANATION.txt — этот файл
  ├── db/
  │   └── init.sql            — SQL-скрипт (для справки, ORM создаёт сам)
  ├── backend/
  │   ├── config.py           — все настройки проекта в одном месте
  │   ├── database.py         — подключение к PostgreSQL через SQLAlchemy
  │   ├── models.py           — ORM-модели (User, Product, CartItem)
  │   ├── schemas.py          — Pydantic-схемы валидации (вход/выход API)
  │   ├── security.py         — хеширование паролей, JWT-токены, авторизация
  │   ├── main.py             — точка входа FastAPI (API-сервер, порт 8000)
  │   ├── admin_app.py        — Flask админ-панель (монолит, порт 5000)
  │   ├── setup_db.py         — скрипт: создаёт БД, таблицы, админа, товары
  │   ├── run.py              — скрипт: запускает оба сервера одной командой
  │   ├── requirements.txt    — Python-зависимости
  │   └── routers/
  │       ├── __init__.py
  │       ├── auth.py         — эндпоинты регистрации/логина
  │       ├── products.py     — эндпоинты каталога товаров
  │       └── cart.py         — эндпоинты корзины
  └── frontend/
      ├── index.html          — единственная HTML-страница (SPA)
      ├── styles.css          — стили (чёрно-белый минимализм)
      └── app.js              — вся логика фронтенда на чистом JavaScript

Принцип микросервисности:
  - FastAPI (порт 8000) — основное REST API (auth + products + cart)
  - Flask (порт 5000) — админ-панель, отдельный монолитный сервис
  - Frontend — статика, открывается в браузере, общается с API через fetch
  - PostgreSQL (порт 5432) — база данных, ставится локально

Админ-панель (Flask) общается с FastAPI через HTTP-запросы (httpx),
то есть сервисы связаны через API, а не через общую кодовую базу.


================================================================================
2. СТЕК ТЕХНОЛОГИЙ И ЗАЧЕМ КАЖДАЯ
================================================================================

BACKEND:
  - Python 3.12          — основной язык, читаемый и популярный
  - FastAPI 0.111        — современный асинхронный веб-фреймворк для REST API,
                           автоматическая документация Swagger на /docs
  - Flask 3.0            — легковесный фреймворк для админ-панели (монолит)
  - SQLAlchemy 2.0       — ORM для работы с PostgreSQL через Python-объекты
                           (защита от SQL-инъекций "из коробки")
  - psycopg2-binary      — драйвер PostgreSQL для Python
  - Pydantic 2.7         — валидация входных данных (автоматически отсекает
                           невалидные запросы ДО попадания в бизнес-логику)
  - python-jose          — создание и проверка JWT-токенов
  - passlib + bcrypt     — хеширование паролей (bcrypt — индустриальный стандарт)
  - uvicorn              — ASGI-сервер для запуска FastAPI
  - httpx                — HTTP-клиент (Flask -> FastAPI коммуникация)
  - python-multipart     — парсинг form-data (нужен FastAPI для форм)
  - email-validator      — валидация email-адресов (нужен Pydantic EmailStr)

FRONTEND:
  - HTML5                — структура страницы
  - CSS3                 — стилизация (чёрно-белый минимализм, responsive)
  - JavaScript (ES6+)    — логика SPA (без фреймворков, чистый JS)

DATABASE:
  - PostgreSQL 16        — надёжная реляционная СУБД, индустриальный стандарт

БЕЗОПАСНОСТЬ:
  - Пароли хранятся как bcrypt-хеши (невозможно восстановить оригинал)
  - JWT-токены с временем жизни (30 минут по умолчанию)
  - Pydantic валидация отсекает SQL-инъекции и невалидные данные
  - SQLAlchemy ORM — параметризованные запросы (защита от SQL-инъекций)
  - CORS middleware — контроль доступа с других доменов
  - XSS-защита — escapeHtml() на фронтенде

4. РАЗБОР КОДА ПОСТРОЧНО
================================================================================

--- backend/config.py ---
Строки 1-5: Настройки PostgreSQL — юзер, пароль, имя БД, хост, порт
             По умолчанию используется стандартный юзер postgres
Строки 7-10: DATABASE_URL — строка подключения к БД формата
             postgresql://user:pass@host:port/dbname
Строки 12-14: JWT настройки — секретный ключ, алгоритм HS256, время 30 мин
Строки 16-17: Логин/пароль админа (admin / admin123)
Строка 19:   Секретный ключ Flask для сессий

--- backend/database.py ---
Строки 1-3: Импорт SQLAlchemy компонентов и DATABASE_URL из конфига
Строка 5:   create_engine — создаёт пул соединений к PostgreSQL
             pool_pre_ping=True — проверяет соединение перед использованием
Строка 6:   SessionLocal — фабрика сессий (каждый запрос = новая сессия)
Строка 7:   Base — базовый класс для всех ORM-моделей
Строки 10-15: get_db() — dependency injection для FastAPI.
              Создаёт сессию БД, передаёт в эндпоинт, закрывает после.

--- backend/models.py ---
Строки 1-4: Импорт типов колонок SQLAlchemy и Base из database.py
Строки 7-17: Модель User:
  - id: автоинкрементный первичный ключ
  - username: уникальный, до 50 символов, индексирован для быстрого поиска
  - email: уникальный, до 100 символов
  - password_hash: хранит ТОЛЬКО хеш (не сам пароль!)
  - role: "user" или "admin"
  - created_at: дата регистрации (UTC)
  - cart_items: связь один-ко-многим с CartItem (cascade delete)

Строки 20-31: Модель Product:
  - id, name, description, price (Numeric — точные деньги), stock, image_url
  - cart_items: обратная связь с корзиной

Строки 34-48: Модель CartItem:
  - user_id, product_id — внешние ключи с ON DELETE CASCADE
  - quantity — количество товара
  - UniqueConstraint — один товар на пользователя (при повторе — увеличиваем qty)

--- backend/schemas.py ---
Pydantic-модели для валидации входных/выходных данных:

Строки 6-9: UserRegister — регистрация:
  - username: 3-50 символов, только a-z, 0-9, _ (regex)
  - email: проверка формата EmailStr
  - password: 8-128 символов
  Если данные не проходят — автоматический ответ 422 с описанием ошибки.

Строки 12-14: UserLogin — простой логин (username + password)
Строки 17-24: UserResponse — что возвращаем клиенту (БЕЗ пароля!)
Строки 27-29: Token — ответ при успешном логине {access_token, token_type}
Строки 32-45: ProductCreate/ProductUpdate — валидация при создании/обновлении
Строки 48-57: ProductResponse — что видит клиент
Строки 60-77: CartItem схемы — добавление, обновление, ответ

--- backend/security.py ---
Строки 1-12: Импорты — JWT, bcrypt, FastAPI зависимости
Строка 14:   pwd_context — настройка bcrypt для хеширования
Строка 15:   oauth2_scheme — извлекает токен из заголовка Authorization: Bearer

Строки 18-19: hash_password() — принимает "mypass" → возвращает bcrypt хеш
Строки 22-23: verify_password() — сравнивает пароль с хешем (True/False)

Строки 26-30: create_access_token() — создаёт JWT:
  - Кладёт в payload: user_id (sub), роль, время истечения
  - Подписывает SECRET_KEY алгоритмом HS256

Строки 33-53: get_current_user() — FastAPI Dependency:
  - Извлекает токен из заголовка
  - Декодирует JWT, проверяет подпись и срок
  - Находит пользователя в БД по ID из токена
  - Если что-то не так — 401 Unauthorized

Строки 56-62: require_admin() — проверяет что role == "admin", иначе 403

--- backend/routers/auth.py ---
Строка 9:   Роутер с префиксом /api/auth

POST /api/auth/register (строки 12-28):
  - Проверяет уникальность username и email
  - Хеширует пароль через hash_password()
  - Создаёт User с role="user", сохраняет в БД
  - Возвращает UserResponse (без пароля!)

POST /api/auth/login (строки 31-40):
  - Ищет пользователя по username
  - Проверяет пароль через verify_password()
  - Если ОК — создаёт JWT-токен и возвращает {access_token, token_type}
  - Если НЕ ОК — 401 (не говорим ЧТО именно неправильно — безопасность)

GET /api/auth/me (строки 43-45):
  - Требует JWT-токен
  - Возвращает данные текущего пользователя

--- backend/routers/products.py ---
Строка 10: Роутер /api/products

GET /api/products/ (строки 13-23):
  - Публичный (без авторизации), пагинация skip/limit
  - Поиск по имени через ilike (регистронезависимый)

GET /api/products/{id} (строки 26-31):
  - Один товар по ID

POST /api/products/ (строки 34-44):
  - ТОЛЬКО для admin (Depends(require_admin))
  - Создаёт товар из валидированных данных

PUT /api/products/{id} (строки 47-64):
  - ТОЛЬКО admin, частичное обновление (exclude_unset)

DELETE /api/products/{id} (строки 67-77):
  - ТОЛЬКО admin, удаляет товар

--- backend/routers/cart.py ---
Строка 10: Роутер /api/cart — ВСЕ эндпоинты требуют авторизацию

GET /api/cart/ — список товаров в корзине текущего пользователя
POST /api/cart/ — добавить товар (проверяет stock, если уже есть — qty++)
PUT /api/cart/{id} — изменить количество
DELETE /api/cart/{id} — удалить один товар
DELETE /api/cart/ — очистить всю корзину

Важно: user_id берётся из JWT-токена, а не из запроса.
Пользователь НЕ МОЖЕТ редактировать чужую корзину.

--- backend/main.py ---
Строка 9:   Base.metadata.create_all() — создаёт таблицы если их нет
Строки 11-15: Создаёт FastAPI приложение с метаданными
Строки 17-23: CORS — разрешает фронтенду делать запросы к API
Строки 25-27: Подключаем все три роутера
Строки 30-45: При старте — создаёт дефолтного admin если его нет
Строки 48-50: Health check эндпоинт /api/health

--- backend/admin_app.py ---
Flask-приложение (монолитная админ-панель):
  - Имеет свои HTML-шаблоны прямо в коде (чёрно-белый стиль)

  - /admin — дашборд: список товаров + форма добавления
  - /admin/products/add — добавить товар (POST через httpx к API)
  - /admin/products/delete/{id} — удалить товар

Скрипт автонастройки — запускается один раз:

Запускает оба сервера (FastAPI + Flask) одной командой

--- frontend/index.html ---
SPA (Single Page Application) — одна страница с секциями:

--- frontend/styles.css ---

--- frontend/app.js ---

7. КАК ПРОСМОТРЕТЬ БАЗУ ДАННЫХ (PostgreSQL через терминал)
================================================================================

Подключиться к БД:

  psql -U postgres -d oshop_db

(Введи пароль postgres)

Полезные команды:

  \dt                              — список всех таблиц
  \d users                         — структура таблицы users
  \d products                      — структура таблицы products
  \d cart_items                    — структура таблицы cart_items

  SELECT * FROM users;             — все пользователи
  SELECT id, username, role FROM users;  — без хешей паролей
  SELECT * FROM products;          — все товары
  SELECT * FROM cart_items;        — все товары в корзинах

  SELECT u.username, p.name, ci.quantity
  FROM cart_items ci
  JOIN users u ON ci.user_id = u.id
  JOIN products p ON ci.product_id = p.id;
                                    — кто что добавил в корзину

  \q                               — выйти из psql

9. КАК РАССКАЗАТЬ ЗА ПРОЕКТ НА СОБЕСЕДОВАНИИ
================================================================================

Пример рассказа:

"Это мой пет-проект — бэкенд онлайн-магазина. Проект в процессе разработки.

АРХИТЕКТУРА:
Я разделил проект на backend и frontend. Backend написан на Python
с использованием FastAPI для REST API и Flask для отдельной админ-панели.
Это показывает микросервисный подход — два независимых сервиса, которые
общаются через HTTP API. Frontend — это SPA на чистом JavaScript без
фреймворков.

БАЗА ДАННЫХ:
PostgreSQL, три таблицы: users, products, cart_items. Связи через внешние
ключи с каскадным удалением. Работаю через SQLAlchemy ORM — это даёт
автоматическую защиту от SQL-инъекций, потому что все запросы параметризованы.

БЕЗОПАСНОСТЬ:
Пароли хранятся как bcrypt-хеши — даже если утечёт БД, пароли не восстановить.
Авторизация через JWT-токены с временем жизни 30 минут. Входные данные
валидируются через Pydantic — невалидные данные отсекаются ДО попадания
в бизнес-логику. На фронтенде есть защита от XSS через экранирование HTML.

РОЛИ:
Два типа пользователей — user и admin. Обычный пользователь может
регистрироваться, логиниться, смотреть каталог, добавлять товары в корзину.
Админ может добавлять и удалять товары через отдельную Flask-панель.
Разграничение доступа реализовано через JWT — в токене хранится роль,
и API проверяет её через dependency injection FastAPI.

ЧТО РЕАЛИЗОВАНО:
- Регистрация и авторизация (JWT + bcrypt)
- Каталог товаров с поиском и пагинацией
- Корзина (добавление, изменение количества, удаление)
- Админ-панель (CRUD товаров)
- REST API с автодокументацией Swagger

ЧТО ПЛАНИРУЮ ДОБАВИТЬ:
- Систему заказов (оформление, история, статусы)
